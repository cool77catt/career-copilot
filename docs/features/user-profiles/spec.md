# Feature Spec - User Profiles

## 1. Objective
Provide a dedicated `Profiles` workspace where a user can:
- Build a global profile from intake inputs
- Manage multiple job-specific target profiles
- Generate and refine profile-specific artifacts (assessment, tailored resume, tailored profile)
- Preserve revision history for all markdown outputs

## 2. Page Information Architecture
- The app navigation must include a `Profiles` item.
- Opening `Profiles` shows two high-level sections:
  - `User Information`
  - `Job-Specific Profiles`

## 3. User Journey
1. User navigates to `Profiles` from the left navigation bar.
2. In `User Information`, user uploads/provides global context (LinkedIn, resume(s), additional notes).
3. System generates and displays a full global user profile markdown.
4. In `Job-Specific Profiles`, user clicks add profile.
5. System can either:
   - Auto-generate suggested job profiles from global profile via agent, or
   - Accept a user-created custom profile
6. User selects a job-specific profile and views generated artifacts:
   - Overall fit assessment
   - Tailored resume
   - Tailored profile for that job target
7. User adds additional context to the selected job-specific profile.
8. System applies that context to the selected profile and also updates the global profile markdown context.

## 4. Functional Requirements

## 4.1 Navigation and Layout
- Add `Profiles` as a first-class navigation destination.
- Profiles page must render exactly two top-level sections:
  - `User Information`
  - `Job-Specific Profiles`

## 4.2 User Information Section
- Purpose: global intake/ingestion of all known user context.
- Inputs must support:
  - LinkedIn profile input
  - Current resume(s)
  - Additional user notes/context
- System generates a full global user profile markdown from intake context.
- User can view latest generated global profile markdown.

## 4.3 Job-Specific Profiles Section
- User can view a list of job-specific target profiles (for example: Senior Software Engineer, Engineering Manager).
- User can click `Add Profile` to:
  - Request agent-generated profile suggestions based on global profile, and/or
  - Enter a custom profile manually
- User can accept/reject suggested profiles.
- Finalized job-specific profiles are persisted and listable.

## 4.4 Job-Specific Profile Detail Workspace
For each selected job-specific profile, show and persist:
- Overall fit assessment generated by agent
- Tailored resume markdown
- Tailored job-specific profile markdown containing:
  - Relevant subset of global profile information
  - Additional profile-specific context

## 4.5 Context Refinement and Upstream Sync
- User can add extra context directly within a job-specific profile.
- Any profile-specific context updates must:
  - Regenerate/update job-specific artifacts as needed
  - Update the main/global profile markdown with additional context so future agent runs benefit

## 4.6 Markdown and Revisioning Rules
- Every profile component is persisted as markdown.
- At minimum, revision these artifact types:
  - Global profile markdown
  - Job-specific tailored profile markdown
  - Job-specific tailored resume markdown
  - Job-specific fit assessment markdown
- Revisions are non-destructive; history must remain accessible.

## 5. Data Model (Conceptual)
- `UserProfile`
  - Stores global profile markdown path references (LinkedIn/resume/additional/global-profile).
- `JobSpecificProfile`
  - `user_id`, `profile_name`, `status`, source metadata (agent/user), timestamps.
- `JobSpecificProfileArtifact`
  - `job_specific_profile_id`, `artifact_type` (assessment/resume/tailored-profile), `version`, `markdown_path`, timestamps.

## 6. API Surface (Feature)
- `POST /profile/update`
- `GET /profile`
- `POST /profile/job-profiles/discover`
- `POST /profile/job-profiles` (manual custom profile)
- `GET /profile/job-profiles`
- `PATCH /profile/job-profiles/{id}` (accept/reject/update)
- `GET /profile/job-profiles/{id}`
- `POST /profile/job-profiles/{id}/generate` (assessment + tailored resume + tailored profile)
- `PATCH /profile/job-profiles/{id}/context` (add profile-specific context + sync to global profile)
- `GET /profile/job-profiles/{id}/artifacts`

## 7. Agent and CLI Requirements
- Job-profile discovery agent must be runnable from API and CLI.
- Profile-assessment/tailoring agent must be runnable from API and CLI.
- Agents must remain isolated in dedicated directories/files.

## 8. Acceptance Criteria
- User can navigate to `Profiles` from navigation.
- Profiles page has the two required top-level sections.
- User Information intake generates and reveals full global profile markdown.
- Job-Specific Profiles supports add/accept/reject/custom profile creation.
- Each selected job-specific profile shows assessment, tailored resume, and tailored profile.
- Additional job-specific context updates both selected profile outputs and global profile markdown.
- All profile artifacts are markdown and revisioned with accessible history.
